# StyleMuse 代码优化说明

本次优化修复了语料更新、质量判断和流式完成状态，并减少查重计算开销。保留现有 Flask、FAISS 和前端技术栈，增加可恢复归档、共享访问密码、生产启动方式及回归验证。

## 已完成的改动

| 范围 | 当前行为 |
| --- | --- |
| 语料缓存 | 按文件内容哈希、解析版本、分块参数识别变化；新增、编辑、删除语料均使旧缓存失效；损坏的 JSON 缓存自动重建 |
| 向量索引 | manifest 绑定分块内容与 Embedding 配置；在独立目录构建新版本，成功后原子更新指针；失败保持旧版 |
| 查重 | 连续重复匹配采用后缀自动机，精确检测部分的复杂度为生成长度加语料长度；近似检查使用重叠窗口及字符频率上界过滤 |
| 检测范围 | 写作后的检查读取未分块源文；标准化 Unicode 与空白，避免空格插入和检索块边界隐藏重复 |
| 检测状态 | 无内容、无源文、检查异常明确区分，未知结果不赋予低风险或通过结论 |
| 审稿 | 校验可选 LLM 审稿的结构、分数、布尔值和结论；规则红线不可被 LLM 高分覆盖，LLM 失败意见参与最终决策 |
| 风格资料 | 风格统计使用未分块原文；生成 Prompt 接入最多 2000 字 Few-shot；检索结果去重并按距离顺序保留 |
| 流式前端 | 识别生成、检查、保存阶段；只有 done 才确认完成；异常保留草稿，不自动重复调用模型 |
| 保存 | 排他创建文章文件，避免同题并发覆盖；审稿与版本 JSON 原子写入；CLI 和 Web 共用保存模块 |
| 作家删除 | 移入 authors/.trash，可按控制台恢复编号还原；正常作者不再因超过 3 个文件而无法删除 |
| 配置 | 拒绝未知字段、控制字符和无效 provider 或 URL；支持清空地址与密钥；正确处理带空格、引号和井号的值；短密钥全部掩码 |
| 访问 | 默认 API 仅本机可用；配置共享密码后支持浏览器会话或 Bearer 请求；写入检查跨站 Origin |
| 上传 | 单请求最多 32 MB、20 个文件；EPUB 解压最多 128 MB、2000 个条目；保存目录限定在当前作家的 output 内 |
| EPUB | 正确读取书名和 spine 顺序，保留段落；备用解析支持不同目录中的 XHTML、HTML 和 HTM |
| 模型配置 | 示例作家继承全局模型，模型调用设置超时和重试上限，版本保存实际生效的模型参数 |
| 部署 | Docker 使用 Python 3.12 和 Waitress；Compose 要求访问密码；锁定依赖，并加入 Python、Node 和启动检查的 CI |
| 日志 | 默认关闭正文及 Prompt 预览；日志 5 MB 轮转，保留 3 个历史文件 |

## 性能结果

同一台机器上的 600 字合成文章，对项目内置的 78,063 字语料进行查重：旧版按 1,161 个分块逐一比较，单次耗时 7.9863 秒；新版对同样分块运行 5 次，中位耗时 0.2435 秒。实际写作改为读取完整源文，新版 5 次中位耗时 0.1319 秒。

这组数据衡量本机样例的查重耗时，不能替代不同文章、语料规模及并发下的 p95，也不代表真实模型的风格表现改善。近似窗口比较仍会随候选窗口数量增长，线性复杂度仅适用于精确连续重复检测。

复测命令：

```bash
python scripts/benchmark_plagiarism.py --author liu_liangcheng --rounds 5
```

## 使用变化

首次使用已有作家写作时，旧格式缓存与索引会失效，需要重新构建；如启用 RAG，会调用已配置的 Embedding 服务。构建索引必须具备有效的 Embedding 密钥。

共享部署在 .env 中设置 STYLEMUSE_ACCESS_TOKEN，使用随机长密码，浏览器打开后输入访问密码。HTTPS 部署设置 STYLEMUSE_HTTPS=1；容器中 .env 只读，配置需在宿主机修改后重新创建容器。模型配置仍按重启生效处理。

作家归档恢复：

```bash
python main.py restore --archive-id 删除时输出的编号
```

本次采用共享密码访问控制；独立用户账号、后台任务队列、跨实例任务恢复、服务端历史查询和真实模型质量评测仍属于后续工作。当前生成、导入及审稿仍会占用服务线程，部署并发应结合实际模型延迟设置。历史索引版本和归档保留在磁盘，清理前需确认不再需要恢复。
